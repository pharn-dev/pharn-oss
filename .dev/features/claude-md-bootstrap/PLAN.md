### Loading mechanisms deliberately not used

No `@` import, no `.claude/rules/` file (with or without `paths:`), and no new guide that every task must read. A path-scoped rule fires when a matching file is opened. ## The measurement constraint that shapes the build

`--growth` counts, per file in both sets, the HEAD lines minus the BASE lines as a line multiset, the positive part only. The budget is 2,048 B (default; there is no `budget` key at base). So a rewritten root file fails however small it is. The build therefore keeps every retained line **byte-identical** to a base line, which costs 0. Only the new index, a CHANGELOG pointer and two truncated-bullet tails are new lines, and their total must stay ≤ 2,048 B. A line moved within one file is free by the checker's own design. Moving text out of the set into a non-loaded guide is not growth. Nothing is moved into another loaded file. The disclosure: the result fits because retained text is kept verbatim, which is also the preservation property this increment wants.

### Dedupe equivalence (107–127 vs `CONTRIBUTING.md` "CHANGELOG entries")

One wording is not literal in the owner: "and records the bump there". The owner implies it through "every PR adds at least one new entry", and the entry is moved into the new section.

## Guarantee audit (P0)

- "Root `CLAUDE.md` shrank to N bytes" → floor: deterministic byte count (`wc -c`). It measures this repo only, never another project's file.
- "The modelled always-loaded set grew by ≤ 2,048 B against `6ff4dd1`" → floor verdict of `check-instruction-files --growth`, over its **model** of the loader, never the loader itself (LIMITS.md §3e).
- "Every base line is kept, moved, or deduplicated to a named owner" → floor-like (a deterministic line multiset comparison by `check-migration.mjs`). It is a one-off script with no tests, so its verdict is evidence, not a repo gate. It proves the text is accounted for, never that a reader finds it in time.
- "Each guide is read before the action it governs" → **advisory.** A pointer is an instruction; nothing forces the read.
- "Workflow behavior is unchanged" → floor for "no executable file changed" (the diff's file list); `npm test` + `validate` GREEN corroborate. Model behavior under the smaller prefix is **not** measured, so no quality, runtime or cost claim is made.

## Trust audit (P2)

No untrusted input enters a decision. The moved text is this repo's own trusted instruction text. The guides gain the authority of a pointer from a trusted file. They sit under `.dev/`, which the write guards protect only through the fail-closed default (as `.dev/floor/` does today). A guide is not hook-protected, the same as `CLAUDE.md` itself.

## Determinism audit (P5)

Each index trigger is a membership test over the task: does it touch a named path set or event, such as editing `.claude/commands/pharn-*.md`, a write deny, or a `docs:check` RED. The fallback when unsure is "read it". A missing or unreadable guide → halt and ask (P6, root constraint 4).
