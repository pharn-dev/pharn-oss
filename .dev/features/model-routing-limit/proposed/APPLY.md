# APPLY — model-routing-limit (human-only patches)

Four patches. One of the four targets a **trusted doc** the agent may not write; the other three target
files the agent _could_ have written but are staged with it so the whole change lands as one coherent
act. Every patch was generated by exact-match substitution and verified in a real worktree of this
repository, not in an out-of-tree sandbox (`.dev/memory-bank/lessons-learned.md` **L26** — a patch
verified against a copy outside the repo is verified under different rules than the repo enforces).

## Why the agent did not apply these itself

`LIMITS.md` is one of the four trusted docs. Probed live this run rather than read off the wiring
(**L37**):

| payload                                                          | hook                        | verdict                    |
| ---------------------------------------------------------------- | --------------------------- | -------------------------- |
| `{"tool_name":"Edit","tool_input":{"file_path":"LIMITS.md"}}`    | `protect-trusted-paths.cjs` | **exit 2** — denied        |
| `{"tool_name":"Write",…{"file_path":".dev/features/…/PLAN.md"}}` | `protect-trusted-paths.cjs` | exit 0 — allowed (control) |

The deny message names the remedy: _"Trusted spec is human-only; the build agent may not write it. If a
change is genuinely needed, a human edits it outside the agent loop."_ That is this file.

## The ordering requirement — read this before you commit

`SKILLS_VERSION` (now `6.3.1`) and the `CHANGELOG.md` `### Added` entry are **already written in the
working tree** by the build stage, and they **assert that `LIMITS.md § 8` exists**. The four patches
below are what makes that assertion true.

**`/pharn-dev-ship` performs no git operations**, so nothing is committed and no such claim has entered
this repository's history. The inconsistency is therefore confined to the uncommitted working tree, and
you resolve it by **applying all four patches before you commit**. Do not commit the version bump and
the changelog entry on their own.

This was raised as the grill's one blocking-severity finding (`GRILL.md`, finding 1) and is recorded
here rather than silently relied on: **nothing detects the mismatch.**
`.dev/floor/check-skills-version-recorded.mjs` binds the CHANGELOG's version key, not the trusted-doc
edit — exactly the blindness `.dev/memory-bank/lessons-learned.md` **L43** records (a consistency check
over several stores of one fact certifies their agreement, never the fact).

## Verify after applying

**COMMIT FIRST, then verify. This ordering is load-bearing and will otherwise cost you a confusing
RED.**

```bash
git add -A && git commit    # stage + commit all four patches together with the version bookkeeping
npm run check               # all 10 gates
```

**Why commit first — measured, not predicted.** `npm run check`'s `check:reconcile` gate REDs on an
_uncommitted_ `pharn/floor/check-model-config.mjs`:

```json
{
  "verdict": "ESCAPE",
  "epoch": null,
  "escapes": [{ "file": "pharn/floor/check-model-config.mjs", "denied_by": "writes-scope (fail-closed default)" }]
}
```

That is **correct behaviour, not a defect in this patch set.** `pharn/floor/**` is deny-by-default in
the fail-closed safe-set, and the always-reconciled control surface is anchored in **committed blob
ids** rather than in the `.pharn/` baseline — which is exactly the property that makes it resist an
actor who can rewrite the baseline. A `git apply` is a **Bash** write, invisible to `PreToolUse`, so
until the change is committed the reconciler correctly reports that a write reached a guarded path
outside the guarded tool surface. Committing makes the blob the committed one and the gate returns
`NO_BASELINE`, which is GREEN by design.

## What this increment does NOT do (P0)

It adds **no control**. PHARN does not attempt to apply a model and fall short — it does not attempt it
at all; `models.stages` is a source of truth the static frontmatter is held to, nothing more. Nor does
it claim the stages run on the _wrong_ model: they may well run on the declared one. The claim is that
**nothing proves it either way**, and that making the executed model observable is platform-level,
invisible to all three floor primitives, and therefore not something a PHARN-side "fix" could deliver
without fabricating a guarantee.
