## Decision proposed at GATE 1 — refuse, in `--check` and in the set alike

**A non-concrete `## Files` item is a refusal (exit 1, nothing written) in both `--check` and a build's set, with no
opt-in.** Reasoning:

- **P7:** three recorded occurrences, the last after L71 named the remedy; L20 and L71 both prescribe a RED.
- **P0:** the refusal reduces to primitive #3 (character membership, the same `isConcrete` that dropped the item, and
  set equality between the items and the scope). As every setter refusal, it is a Bash-run program's verdict
  (L19, `pharn/LIMITS.md §6`), and a command's act of invoking `--check` is ADVISORY orchestration.
- **Why not a warning:** a warning on stderr is the printed count again — someone has to read it, which is the
  discipline remedy L20 says recurs. It recurred three times.
- **Why the set refuses too, not only `--check`:** the setter's header promises that `--check`'s exit 1 "is the refusal
  a build's Step 0 would meet". A `--check`-only refusal would break that parity, and a plan that skipped `--check`
  would still build with a silent under-grant.
- **Why no opt-in:** such an item never granted a write (the setter dropped it, the hook denied the writes it covered,
  reconcile judged against the dropped scope), so refusing it removes no capability, only the impression that it did.
- **Cost, stated:** the `docs/capabilities/**` "regenerated only if the catalog moves" item that 16 dev plans carry is
  now refused; such a path goes under a `### …` heading after the list, or is named file by file when it does change.
  An installed project's plan with a `src/**` item is refused at `/pharn-plan`'s `--check`, which tells the planner to
  name the files. A plan approved before 7.21.0 that holds such an item now stops at Step 0 with the same message.
