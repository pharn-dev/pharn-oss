# APPLY — wiring the `/pharn-loop` Stop guard, for a human

`.claude/settings.json` is **human-only**: `protect-trusted-paths.cjs` denies every Write/Edit to it (fix #2).
The agent that built `loop-stop-guard` did not and could not edit it through the write tools. Until you
apply this, `.claude/hooks/require-loop-record.cjs` ships **inert**: the file exists and is tested, and
nothing starts it.

## The order (and the rollback)

1. **The hook file first.** It lands with this PR (`.claude/hooks/require-loop-record.cjs`).
2. **Then the wiring**, below.
3. **Then `README.md`.** Its `## What gets installed` section says the Stop guard lands inert "as of
   `6.11.1`", because the shipped `settings.json` does not register it. Once this wiring ships, that
   sentence is false: name the release that wires it instead. The rule before it ("it does nothing
   unless your settings register it") stays true.
4. **Rollback is the reverse:** remove the `Stop` block from `settings.json` first, then the file. A
   wired entry pointing at a missing script is a non-blocking error (`node` exits 1 with `Cannot find
module`). That means the guard is off, and it cannot trap a turn.

For an existing install: `pharn update` copies the new `.cjs`, but it never edits `settings.json`, so
the wiring reaches an install only by applying this by hand.

## The entry (verbatim — `hook-wiring.test.cjs` checks this exact line)

```text
{"type":"command","command":"node","args":["${CLAUDE_PROJECT_DIR}/.claude/hooks/require-loop-record.cjs"],"timeout":10}
```

- **Matcher-less.** Stop has no matcher support, per the hooks reference.
- **Exec form.** With `command` + `args` and no shell, the placeholder is substituted as one argument.
  This is the form the reference prescribes for a path placeholder, and it retires the `LIMITS.md §7`
  quoting bound for this hook.
- **`timeout: 10`**, so a stalled guard cannot hold every turn end for the 600 s default. A canceled hook
  renders no decision, which is the fail-open direction.

## What to expect once wired (cosmetic, not a bug)

A refusal renders in the UI as a **"Stop hook error"** (anthropics/claude-code#34600), because it uses
`decision: "block"`. The documented non-error alternative is `hookSpecificOutput.additionalContext`, which
shows as "Stop hook feedback". Switching to it is a one-line follow-up in the hook.

## Proposed text for the human-only trusted docs (not applied)

**`LIMITS.md §7`** — append a bullet:

> - **The `/pharn-loop` Stop guard acts only when Claude Code starts it, and it fails OPEN.**
>   `require-loop-record.cjs` refuses a turn end, at most three times per run, while an unattended loop
>   run open in this session has no `LOOP.md`. It cannot make a model do work, cannot judge the record,
>   and is satisfied by any non-empty file. A hook that cannot start, times out, or crashes lets the turn
>   end, which is the safe direction for a guard that ends turns. Its wiring is exec form, so the
>   quote-character bound above does not apply to it.
