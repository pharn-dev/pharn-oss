# APPLY — `pharn/ARCHITECTURE.md`, for a human

`pharn/ARCHITECTURE.md` is **human-only** and hook-denied (fix #2). The agent that built `gate-run-stamp`
did not and could not edit it through the write tools. This is the staged patch, for you to apply outside
the agent loop.

## Why this exists

The increment adds an **eleventh** contract, `pharn/pharn-contracts/gate-run-record.md`. `§4`'s layer tree
enumerates the contracts **by name**, so it now reads as a list of ten and is stale the moment the new file
lands. Nothing in the repository detects that: the trusted docs are `.prettierignore`'d, markdownlint-
excluded, and no checker reads their prose. The README's equivalent list is inside the generated
`CURRENT-STATE` region and regenerates cleanly; this one cannot.

**Surfaced by the grill, not after the fact.** `/pharn-dev-grill` raised it as finding **R2** against the
plan, before any code was written — the plan had swept the README and missed the trusted doc, which is
`lessons-learned` **L50** exactly (sweep the cites of the referent that moved, not the claim's spellings).

## Verification already done

The patch below was **generated by making the edit in a real `git worktree` of this repository and diffing
it**, then re-checked with `git apply --check` against a **second, clean worktree at the real path** — exit 0. It is not a hand-written hunk, and it was not verified against a sandbox copy outside the repo:
`lessons-learned` **L26** records why that distinction matters, since config-driven gates resolve by PATH,
so a copy outside the tree is judged under different rules than the repo enforces. Both worktrees were
removed afterwards.

## What it changes, and what it deliberately does not

- **Changes:** `§4`'s contract enumeration gains `gate-run-record`, taking it from ten names to eleven.
- **Does not change:** `§2`'s three floor primitives. This increment adds **no new primitive** — the
  stamp's guarantees reduce to primitive #2 (content-hash, the between-gates fingerprint chain) and
  primitive #3 (enum/regex, the coverage and ordering membership tests), both already listed.
- **Does not change:** `§6`'s pipeline-spine table. `verify-report` and `regression-report` keep their
  existing artifact rows; the `gate_run` block is an **additive, advisory** field inside them, documented
  in those two contracts rather than in the spine.

## After applying

`SKILLS_VERSION` already counts this increment's bump, and the four trusted docs all ship, so no further
version action is needed. If you decline the patch, the honest consequence is a stale enumeration in a
trusted doc — record that choice somewhere a later reader will find it, because nothing in the repository
will flag it again.
