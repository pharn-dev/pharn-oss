## Why this is needed — a claim in `LIMITS.md` EXPIRED the moment this increment shipped

`LIMITS.md §6` currently reads:

> a `Bash` write is **neither denied nor detected at the time it happens**

The first half is still true and stays. **The second half became false when
`pharn/floor/check-bash-reconcile.mjs` shipped.** This is lessons-learned **L33** precisely — forward-
looking prose that is true when written and false the moment the work lands, in a file nobody is
editing, with **nothing** detecting the transition: the four trusted docs are `.prettierignore`d and
markdownlint-excluded, and no checker reads their prose. **L33's polarity note applies too:** this is
prose that now **understates** the repo, which is why it would survive review — an honest-sounding "not
detected" reads as conservative.

## What each hunk does

### `LIMITS.md` — 3 hunks, all inside §6

1. **Splits the expired sentence.** "neither denied nor detected" becomes "**not denied**, and **not
   detected at the time it happens**" — preserving the true half exactly.
2. **Adds the detection half, with all four bounds and two struck claims.** Names the mechanism, states
   that detection is **strictly weaker** than prevention, records the one-worktree bound as inherited
   from **L38**, and strikes "the detector cannot be disabled" in favour of the claim that actually
   holds: _it cannot be disabled quietly_. Also demotes the old `check-regress scope` backstop to
   "older, advisory, still present" rather than deleting it — it is a different check with different
   bounds and it did not go away.
3. **Adds a closing paragraph: detection did not CLOSE the limit.** The section must not be read as
   resolved. A detected write already happened; the reconciler reports and never reverts; rollback is
   out of scope. This is the hunk most worth your scrutiny, because it is the one guarding against the
   increment being remembered as more than it is.

### `THREAT-MODEL.md` — 2 hunks

1. **§3, the `memory poisoning` row.** §2 #3 calls this "the worst persistence vector". The row now
   records that canon is `never_exempt` in the reconciler, so a Bash write to it between build and
   verify REDs the stage — **unhooked but no longer undetected**.
2. **§4 item 7 (`reads`/`writes` declared not enforced).** `writes:` is no longer _merely_ a declaration
   on the Bash surface; it is an unenforced boundary whose violation now costs a red stage.
