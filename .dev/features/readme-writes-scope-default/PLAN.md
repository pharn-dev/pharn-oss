## The failure this closes (P7 — a real, observed defect, measured not reasoned about)

`.pharn/**` is **not** a member of the fail-closed default-safe-set. It is `ALWAYS`
(`enforce-writes-scope.cjs:120`), composed **unconditionally** into the allow-list at
`:317` — `allow = [...ALWAYS, ...(scope || defaultSafeSet())]` — so it is permitted **with a set scope
too**. Both sites below file it under the default, which gets its source _and_ its consequence wrong.

Probed live this run, in a throwaway installed-project fixture (`pharn.config.json` carrying
`skillsVersion`, no `.dev/floor/`):

```text
# no scope file  ->  fail-closed default
exit=0  features/x/PLAN.md
exit=0  .pharn/scratch.json
exit=2  .pharn/writes-scope.json      # DENIED BY NAME at :314, before the allow-list is consulted
exit=2  src/app.ts   package.json   README.md   memory-bank/lessons-learned.md

# scope SET from a PLAN's `## Files` = ["src/app.ts", "package.json"]
exit=0  src/app.ts
exit=0  package.json
exit=0  .pharn/scratch.json           # STILL allowed -> `.pharn/**` is ALWAYS, not the default
exit=2  features/demo/PLAN.md         # LOST -> a set scope REPLACES the default
exit=2  README.md
```

### Defect A — `README.md` `## Current limitations` (4 errors in one bullet)

1. "no scope is active … restricted to `features/**` and `.pharn/**`" attributes `.pharn/**` to the
   **default**. It is unconditional; the sentence implies setting a scope removes it. It does not.
2. "`.pharn/**`" is a universal claim that is **false for `.pharn/writes-scope.json`** — the guard's own
   input, denied by name. This is **[[L37]]'s own defect (1) recurring**: L37 was promoted from these
   very sentences, and the repair replaced the quantifier `only` with `restricted to` while leaving the
   unlisted exception unstated. A new spelling of the same quantifier.
3. "PHARN's product pipeline artifact directories" is wrong for `.pharn/`, which `CLAUDE.md` defines as
   **gitignored runtime state** (plus one load-bearing cache). Only `features/**` is an artifact dir.
4. The remedy "set a scope that names those paths" is presented as purely additive. Measured above, a
   set scope **replaces** the default: a user who follows it to reach `src/app.ts` **loses**
   `features/**`, i.e. the pipeline can no longer write its own artifacts. The trade is not stated.

### Defect B — `.claude/commands/pharn-review.md:83-87` (product surface, and the sharper one)

> "With no scope file, `enforce-writes-scope.cjs` permits its install safe-set, which is **exactly
> `features/**`** — the same set this command's `writes:` declares. So the honest guarantee is **"this
> command writes only inside `features/**`"**, and **NOT** "exactly the three artifact paths"."

Measured above: `.pharn/anything.json` exits **0** under that same no-scope default. The enforced width
is `features/** ∪ .pharn/**`, so "exactly" is false, "the same set this command's `writes:` declares"
(`writes: ["features/**"]`) is false, and the stated "honest guarantee" is **narrower than what the
floor actually permits** — in a passage whose entire point is that it is "written at its real width".
This is the [[L37]] class on the **shipped** surface: `/pharn-review` is the one command that sets no
scope of its own, so this default _is_ its live enforcement boundary.

## How the cited lessons were applied

- **L19** — a stage's Bash-run tooling escapes `writes:` scope. Declared here, not pretended away: this
  run executes in a **detached git worktree** outside the session's repo root, so the fix #7 `PreToolUse`
  guard has **no jurisdiction over any write in it** (every scope entry is repo-root-relative) and every
  edit below goes through **Bash**. fix #7 is therefore **advisory for this run** — stated, not hidden.
  The two scoped formatter calls and `npm run docs:generate` are Bash writes for the same reason.
- **L25** — a rationale comment reaches only the file it sits in, and is trusted for the defects it does
  not name. This is the mechanism of both defects: `enforce-writes-scope.cjs:112-127` explains the
  install/dev partition correctly and `CLAUDE.md:356` states the `.pharn` carve-out correctly ("replaces
  the safe-set **for non-`.pharn` zones**") — and two other files still got it wrong, because a correct
  comment has no reach. The remedy is applied where the reader is, not by improving the comment.
- **L33** — a claim class does not ship in one spelling; treat the first grep as a lower bound to beat.
  The bullet the maintainer pasted was one site; sweeping `safe[- ]set` case-insensitively across
  `*.md`/`*.cjs`/`*.mjs`/`*.json` surfaced **Defect B on the product surface**, which no reading of the
  README would have reached. Two further hits were checked and are **correct as written** (`README.md`
  `:289` and `pharn/floor/README.md:108` both say only "fail-closed to a default-safe-set", quantifying
  nothing) and are deliberately left alone.
- **L36** — a per-member presence set is not a closed set; the parameterized fragment is what drifts.
  Applied as the reason the sweep keyed on the **stem** (`safe[- ]set`) rather than on the bullet's own
  sentence: `exactly features/**`, `restricted to`, and `only paths` are three spellings of one claim,
  and only the stem scan is closed over them.
- **L38** — concurrent sessions contend for the single `.pharn/writes-scope.json`, and the scope check
  then reports a false cause; the remedy is to run the stage from an **isolated detached worktree**. Cited

  the shields badge. The evidence is the probe recorded above, not a gate.

- **No new floor primitive is added, and none is proposed.** The named residual
  `default-safe-set-doc-pin` (recorded in `.dev/features/writes-scope-default-disclosure/PLAN.md:149`)
  stays deliberately unbuilt. Per **L20** the trigger for escalating a discipline-only remedy is a
  second occurrence — and this _is_ one for L37's class, so the refusal is argued rather than assumed.
  **It does not rest on impossibility, and the first draft of this audit was wrong to say so** (caught by
  this increment's own grill, finding 1): a crude enum-regex check IS constructible — invert the stem scan
  this plan already ran and assert that any file naming the default-safe-set also names the
  `writes-scope.json` exclusion. It rests on **value**: that checker pins one exception's spelling while
  leaving every other property of the sentence — the ALWAYS-vs-default attribution, the replaces-vs-adds
  trade, both of which are defects here — completely unguarded, so it would report GREEN over a bullet
  wrong in three of its four claims. A check that certifies the narrowest error class is worse than the
  named residual it replaces, because it reads as coverage. What is applied instead is L37's own remedy:
  probe, don't read, and record the exit code beside the sentence.
