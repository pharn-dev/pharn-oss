# APPLY — `pharn/ARCHITECTURE.md`, for a human

`pharn/ARCHITECTURE.md` is **human-only** and hook-denied (fix #2). The agent that built
`loop-cost-ledger` did not and could not edit it. This is the staged patch, for you to apply outside the
agent loop.

## Verification already done

`architecture.patch` was **generated by making the edit in a real `git worktree` of this repository and
diffing it**, then re-checked with `git apply --check` against a clean worktree at the **real path**. It
is not a hand-written hunk, and it was not verified against a sandbox copy outside the repo —
`.dev/memory-bank/lessons-learned.md` **L26** records why that distinction matters: config-driven gates
resolve by PATH, so a copy outside the tree is judged under different rules than the repo enforces.

```bash
git apply --check .dev/features/loop-cost-ledger/architecture-patch/architecture.patch   # expect: silent, exit 0
git apply         .dev/features/loop-cost-ledger/architecture-patch/architecture.patch
```

## What it changes — two hunks, and the first carries a decision that is yours

### Hunk 1 — the contract list (`§4`, the layer tree)

Adds `cost-ledger`, **and closes a pre-existing drift this increment surfaced rather than caused**:

> `pharn/pharn-contracts/` holds **9** contracts on disk. `ARCHITECTURE.md` named **6**.
> `reconciliation-record`, `regression-report` and `verify-report` were already missing before this
> increment touched anything.

Adding `cost-ledger` alone would have made it **10 named 6**. The patch therefore lists all ten. **That
is a judgment call that belongs to you, not to the agent** — which is why the drift is reported here
rather than quietly folded in:

- **Apply as-is** to close the pre-existing drift in the same edit.
- **Apply, then delete the three names you did not ask for**, if you would rather this increment change
  only what it introduced.
- **Take only the `cost-ledger` addition** and close the rest in its own commit.

Nothing detects either choice. No checker reads this prose — the four trusted docs are `.prettierignore`d
and markdownlint-excluded, and `validate.mjs` does not walk root docs. That absence is exactly why this
is on paper in front of you (**L33**, **L37**).

### Hunk 2 — the durable per-feature files (`§5`, State)

Adds `cost.json` beside `findings.json` and `ship-record.json`. `cost.json` is committed on a green
`/pharn-loop` stop and left in the working tree on every other stop, so it is durable per-feature state
by the same definition that sentence already uses.

## What this patch deliberately does NOT do

- **It makes no guarantee claim.** `cost-ledger.md` is a schemas-only contract in L-1. The floor
  primitives it reduces to are named in the contract itself and in `pharn/floor/check-cost-ledger.mjs`'s
  header — not here, and not in `ARCHITECTURE.md`.
- **It does not touch `§2` (the floor) or `§6` (the pipeline spine).** The cost ledger adds **no** floor
  primitive and **no** pipeline stage: `check-cost-ledger.mjs` is enum/regex plus an arithmetic
  recompute — primitive #3 — and the ledger is an artifact of an existing stage's stop, not a new stage.
- **It does not describe the ledger as gating anything**, because it does not. A RED ledger never blocks
  the `/pharn-loop` commit, which stays gated on `STOP_GREEN` ∧ the decision re-derivation (fix #3).

## If you would rather not apply it

Nothing breaks and no gate turns red. `ARCHITECTURE.md` would continue to under-list the contracts
directory — the state it was already in for three of them. The cost of skipping it is that a reader
deriving the contract set from `§4` gets an answer four names short.
