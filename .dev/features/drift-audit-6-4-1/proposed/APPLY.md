## The ordering requirement — read this before you commit

1. **Apply nothing until the chain has finished.** `pharn/ARCHITECTURE.md` is content-hashed into `PLAN.md`'s `spec_content_hash`. `ARCHITECTURE.md.patch` changes that hash, so applying it while a build is pending makes the build refuse with "the spec drifted". At GATE 2 the chain is done.
2. **Apply every patch in the list below before you commit.** The `6.4.2` bump and the CHANGELOG entry assert that the trusted-doc corrections exist. **Nothing detects a skipped patch:** `check:badge` and `check:changelog` certify that the version agrees across stores, never that the change it names happened (`lessons-learned` **L43**). Do not commit the bookkeeping on its own.
3. **Commit first, then run `npm run check`.** A `git apply` is a Bash write, so `check:reconcile` reports an uncommitted change to a trusted doc as an escape. Committing makes the blob the committed one and the gate returns `NO_BASELINE`, which is GREEN by design.
